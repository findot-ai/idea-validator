# 3단계 — 검증 (싼 실험)

**목적:** make-or-break를 **코드 최소·비용 최소**로 실측. 예측을 실험으로 갈아치운다.

## 입력
2단계 핸드오프의 make-or-break

## 할 일
1. **실험 설계 — "지을 것 없이 답이 나오는 최소 형태"**
   - 렌더 프로토타입 / 수동 리스트 / 목업 / 공개 데이터셋 대체 실행 / 유료 파일럿.
   - **대조군 필수** (예: 새 방식 vs 지금 방식).
   - 실제 데이터를 못 구하면 "상한/하한 케이스"로 대체하고 그 방향을 명시 (예: "이 대체 데이터는 실제보다 유리한 상한이다").
2. **예측 기록 → 실측 → 갱신**
   - 실험 전 분석가 예측을 먼저 적는다.
   - 정량 지표로 측정 (대조군 대비 몇 배·몇 %p).
   - 예측이 틀렸으면 "과대/과소평가했다"를 명시하고 판정 갱신.
3. **결과 해석**
   - 통과 조건과 실패 조건을 함께 (예: "기본값은 새 방식, 사용자가 원래 방식으로 되돌릴 수 있으면 통과").
   - 실험이 답하지 않은 항목은 "미검증"으로 남긴다.

## 규칙
- 실측 없이 판정 금지.
- 결과가 좋아도 나빠도 그대로. **좋은 결과가 나와도 최종 품질 판정은 사용자가 한다** — 품질 기준은 사용자가 정한다.

## 회사 신사업 모드
- 실험 설계를 아래 **실험 카드** 형식으로도 낸다. 팀이 바로 실행하고 판정할 수 있게 하기 위해서다.

```
가설: <누가 / 무엇을 하면 / 어떤 변화가>
선행 지표 / 결과 지표:
성공선 / 실패선: (실험 전에 적는다)
최소 실행: <지을 것 없이 확인하는 방법>
기간 · 비용:
```
- 성공선·실패선은 실험 전에 적는다. 측정 장치(이벤트·UTM·설문)가 준비되지 않으면 시작하지 않는다.

## 출력 → 핸드오프
- 예측 vs 실측 표 + 수치
- make-or-break 판정: 통과(조건) / 실패
- 미검증 항목
- 갱신된 전체 판정
