# 2단계 — 구조화 (게이트 + 스코어카드 + make-or-break)

**목적:** 사실 위에서 구조적 벽을 찾고, 건너야 할 **단 하나**를 특정.

## 입력
1단계 핸드오프

## 할 일
1. **게이트 G1→G5 순서 통과.** 앞 게이트 실패 시 즉시 기각, 뒤는 생략(분석 비용 절약).
2. **지불5요인 채점:** 정보비대칭 / 감정 / 즉시성 / 비대체성 / 반복 — 각 강/중/약 + 근거.
   - 감정 의존 아이템은 G4로 되돌려 재확인.
   - 반복이 낮아도 per-use 가치가 극단적이면 프리미엄 일회성 성립 가능함을 명시.
3. **콜드스타트:** 유저 0명일 때 첫 유저에게 완결적인가.
4. **플랫폼 완결성:** 타겟 플랫폼 제약 안에서 끝까지 작동하는가 (미니앱 플랫폼의 외부 링크 금지, OAuth 불가 등). 안 되면 "이 플랫폼엔 못 올림" + 대체 플랫폼.
5. **해자 명명:** 데이터·관계·도메인·유통 중 무엇인지. 없으면 "해자 없음".
6. **make-or-break 특정:** 통과/조건부면 "이것 하나만 확인되면 간다"를 1개(최대 2개)로 압축 + "가장 싸게 확인할 방법" 초안.

## 규칙
- 아이디어를 살리려고 전제를 바꿔 해석하지 않는다. 바꾸면 "리프레임" 명시 → 새 아이디어.
- 산출물이 아니라 "주도한 일/해결하는 문제" 단위로 본다.

## 출력 → 핸드오프
- G1~G5 각 통과/실패 + 한 줄 근거
- 지불5요인 스코어카드
- 판정: 통과 / 조건부 / 기각(사망 벽 + 기각 로그)
- make-or-break 1~2개 + 확인 방법 초안
